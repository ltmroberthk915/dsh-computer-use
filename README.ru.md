# Computer Use в стиле Codex

**Самый точный способ управлять Windows из DeepSeek Harness — и самый дешёвый в расчёте на задачу.**

Опишите цель. Агент считывает точные идентификаторы элементов управления, действует через сами элементы, проверяет результат — и выполняет известную последовательность за один цикл обращения к модели вместо десяти.

## Почему он самый точный

- **Идентификаторы, а не догадки.** UI Automation предоставляет реальное дерево элементов управления с точными `AutomationId`, а действия могут управлять элементом через его собственные шаблоны UI Automation вместо кликов по координатам.
- **Метки проверяются, а не принимаются на веру.** По умолчанию нумерованная метка сверяется с идентичностью окна и выборочно проверенными пикселями до отправки любого ввода, поэтому устаревшая метка отклоняется, а не приводит к клику в неверном месте. Когда анимированный соседний элемент постоянно нарушает пиксельную подпись, `uiaOnly` привязывает идентичность к дескриптору окна и геометрии, при этом проверка перекрытия в момент отправки по-прежнему выполняется.
- **Запросы остаются ограниченными.** Запросы UIA по умолчанию используют глубину 6, 120 узлов и мягкий бюджет 1200 мс; запрос глубже 6 или содержащий больше 300 узлов требует измеренного `anchor`, поэтому запрос не может незаметно обойти неверную область.
- **Если не видно — прочитайте.** `computer_ocr` возвращает строки и рамки каждого слова в абсолютных пикселях экрана, поэтому приложения без поддержки UIA можно находить по названию.

## Почему это дешевле

- **Один цикл для известной последовательности.** Один вызов `computer_batch` последовательно выполняет список действий, останавливается на первой ошибке и стоит один цикл обращения к модели вместо одного на каждое действие.
- **Возвращается только разница.** Передайте идентификатор предыдущего наблюдения в `since` и получите добавления, изменения, удаления и порядок — а не всё дерево заново.
- **Компактные отчёты по умолчанию в 2.0.0.** Текст после действия обычно добавляет не более 6 КиБ к отчёту о действии; `feedback: full` по-прежнему доступен, когда важнее подробность.
- **Доказательства не попадают в диалог.** Полные доказательства по точке могут храниться в ограниченном локальном кэше (4 МиБ памяти, 32 МиБ на диске, 64 записи, срок 24 часа) и извлекаться по запросу.
- **Локальная работа остаётся локальной.** UI Automation, OCR экрана и проверки пикселей выполняются в готовом нативном воркере — без дополнительных расходов на компьютерное зрение на каждом шаге.

## Создан для рабочего стола, которым вы продолжаете пользоваться

- **Он ждёт вас.** Уведомление за 1 секунду до ввода (0,1 секунды в пределах скользящего 3-минутного окна) сразу возвращает вам рабочий стол; когда вы закончите, агент повторно наблюдает состояние и продолжает исходную задачу.
- **Тормоз доходит до модели.** `Ctrl+Esc` приостанавливает, `Ctrl+Alt+R` возобновляет, `Ctrl+Alt+Q` завершает работу, а остановка передаётся в текущую сессию. Подтверждения по умолчанию включены, а ввод в поля паролей по умолчанию отклоняется.
- **Он сообщает о том, чего не может.** Защищённый рабочий стол Windows (запрос UAC или экран блокировки) обнаруживается, о нём сообщается, а после него работа возобновляется — без слепых повторных попыток.

## Что он делает

Версия 2.0.0 также использует компактный синий указатель-«воздушный змей» во время работы ИИ и удержания сцены. Его наклонённый кончик отмечает точку клика, а внутри змея размещены маленькие символы текста и изменения размера. «Дышащий» змей означает, что страница и положение указателя должны оставаться на месте; свободный режим возвращает приложению обычный курсор. Тема курсора Windows пользователя сохраняется.

Версия 2.0.0 ограничивает обход UIA и по умолчанию использует компактный текст после действия. Существующая обратная связь в виде изображений остаётся доступной; `feedback: compact|full|none` управляет степенью подробности, а параметр клика `verificationRegion: "x,y,w,h"` задаёт ожидаемую область эффекта независимо от точки ввода. Компактный текст обычно добавляет не более 6 КиБ к исходному отчёту о действии. Полные доказательства по точке можно сохранять в ограниченном локальном кэше с истекающим сроком и извлекать по запросу. При сбое диска происходит возврат к ограниченной памяти; если не удаётся сохранить ни одного извлекаемого снимка, текущие доказательства возвращаются полностью прямо в ответе, вне рамок компактного бюджета, без дополнительного наблюдения или ввода.

Отфильтрованные запросы UIA требуют `hwnd`. По умолчанию используются глубина 6, 120 узлов и мягкий бюджет 1200 мс. Запрос глубже 6 или содержащий больше 300 узлов требует измеренного `anchor:"x,y"` в этом окне; точный `id` не обходит это правило. Вызов провайдера может превысить мягкий бюджет, а частичные результаты не позволяют доказать отсутствие или уникальность. После сочетания клавиш управления окнами проверьте `computer_state {windows:true}`, успешно активируйте нужное окно и получите его наблюдение, прежде чем продолжать ввод с клавиатуры.

- **Наблюдение** — список окон, снимки экрана (область / JPEG / PNG / с уменьшением), карта Set-of-Marks
  кликабельных элементов и дерево UI Automation с точными `AutomationId`.
- **Действие** — клик, перемещение, перетаскивание, прокрутка, выделение диапазона текста, ввод, нажатия клавиш
  и управление элементами через их собственные шаблоны UI Automation вместо слепых координат.
- **Пакет** — один вызов `computer_batch` последовательно выполняет список действий и останавливается
  на первой ошибке, поэтому известная последовательность стоит один цикл обращения к модели вместо десяти.
- **Вопрос** — `computer_ask` задаёт вопрос на той же карточке чата, которую DSH использует для
  `ask_user_question`, без обратного отсчёта.
- **Человеческий тормоз, который доходит до модели** — остановка передаётся в текущую сессию, поэтому агент
  узнаёт о прерывании, а не обнаруживает его на следующем шаге.

Инструменты наблюдают за рабочим столом, а не сканируют документы пользователя. Плагин управляет нативными помощниками в
`%LOCALAPPDATA%\dsh-computer-use\worker\`, а также журналами аудита, снимками экрана и собственным ограниченным
`observation-cache` в `$DSH_HOME/data/computer-use/`. `computer_ctrl {action:"clear_cache"}` очищает
кэш наблюдений этого Агента; он не удаляет снимки экрана, вложения или документы пользователя.

## Установка и обновление в dsh-market

Найдите в маркетплейсе **computer-use** или **Codex-style**. Выберите репозиторий **ltmroberthk915/dsh-computer-use** и npm-пакет **dsh-codex-style-computer-use** (сопровождающий: **ltmroberthk**), затем нажмите **Установить**. Для обновлений по стабильному каналу используйте **Обновить** или **Обновить все**. Оба нативных помощника включены; PowerShell 7 или разрешение на сборку не требуются.

Либо введите **`dsh-codex-style-computer-use`** в **Настройки → Плагины → Добавить плагин** для текущего стабильного канала или **`dsh-codex-style-computer-use@2.0.0`** для версии, описанной на этой странице. Указывайте спецификацию npm-пакета напрямую. Ваш хост может применять период ожидания к новым версиям; следуйте его указаниям. Вновь добавленный бандл может загрузиться на лету на поддерживаемых хостах; проверьте, что его инструменты и skill появились. Перезапустите DSH из трея при замене уже загруженной версии, если клиент остаётся устаревшим или если DSH сообщает **restart-required**.

### Выпуски, опубликованные менее 24 часов назад

Конфигурация pnpm 11.7.0 по умолчанию (нестрогая) автоматически записывает исключение для одной версии и выполняет установку. Успешная установка на одной машине не означает, что другая машина разрешает свежие версии.

При `minimumReleaseAgeStrict: true` (или политике хоста, включающей строгие проверки возраста выпуска) и при отсутствии подходящего исключения версия, не достигшая заданного возраста, отклоняется до запуска кода плагина. Для голого имени, точного закрепления `@1.2.0` и URL npm-архива проверено, что при такой политике все они завершаются ошибкой `ERR_PNPM_NO_MATURE_MATCHING_VERSION`. Явное указание `minimumReleaseAge: 1440` также включает строгое поведение в pnpm 11.7.0, если только `minimumReleaseAgeStrict` отдельно не установлен в false. Перезапуск DSH, установка PowerShell или повтор той же команды не устраняют отказ по строгой политике. Официальный мост приложения Desktop не принимает дополнительные флаги pnpm.

Если строгая политика блокирует установку, дождитесь, пока версия достигнет заданного возраста, и устанавливайте, не меняя политику. Версия 1.2.0 опубликована в `2026-10-03T03:50:11.586Z`; 24-часовой порог она проходит после **2026-10-04 03:50:12 UTC** (11:50:12 по времени Китая). Более длинный настроенный порог или отстающее зеркало реестра могут дополнительно отложить доступность. Пользователям с конфигурацией по умолчанию (нестрогой) не нужно ждать или менять конфигурацию для этого пакета.

Если вы явно решаете установить раньше, добавьте это исключение для одной версии в существующий `pnpm-workspace.yaml` целевого профиля, а затем повторите установку из маркетплейса. Сохраните остальные записи; не отключайте глобальную политику возраста:

```yaml
minimumReleaseAgeExclude:
  - dsh-codex-style-computer-use@1.2.0
```

Путь по умолчанию для профиля desktop — `%USERPROFILE%\.dsh\profiles\desktop\pnpm-workspace.yaml`; используйте фактический каталог, если `DSH_HOME` изменён. После того как версия «созреет», это единственное исключение можно удалить.

Прежние исправления документации и проверки публикатора не изменили среду выполнения 1.2.0 и не требовали переустановки. Исправление нативного внимания в **1.2.1** действительно требует обновления. Повторное добавление того же источника на некоторых путях установки может вызвать ошибку хоста `ambiguous-install`; переустановка 1.2.0 не применит исправление 1.2.1.

**Миграция более старой установки Git/tarball из этого репозитория:** удалите в маркетплейсе старую запись **dsh-computer-use**, затем установите **dsh-codex-style-computer-use**. Имя npm без скоупа `dsh-computer-use` принадлежит другому репозиторию; не устанавливайте его как обновление этого плагина. Установка из Git не может сменить идентичность зависимости, просто получив новый коммит. После этой однократной миграции в интерфейсе используйте обычные обновления из маркетплейса. Существующие имена инструментов `computer_*` и пространство настроек `computer-use` сохраняются.

**Сохраните и свою конфигурацию:** сделайте резервную копию `cordis.patch.yml` профиля, затем измените только `name: dsh-computer-use` в переопределении с `id: computer-use` на `name: dsh-codex-style-computer-use`. Сохраните целиком поля `config` и `disabled`. Одного лишь сохранения пространства настроек недостаточно: при несовпадении имени DSH пропустит даже переопределения `read-only`, `dryRun` и отключённого состояния. Не заменяйте глобально другие плагины или общий патч уровня home. Скрипт репозитория `scripts/migrate-profile.mjs` по умолчанию показывает предварительный просмотр; `--apply` создаёт резервную копию и атомарно заменяет файл, отказываясь от параллельных изменений.

Либо скачайте [утилиту миграции конфигурации](https://github.com/ltmroberthk915/dsh-computer-use/releases/download/v1.2.0/computer-use-profile-migration.zip), распакуйте её и дважды щёлкните `migrate-profile.cmd`. Она находит установленное официальное приложение Desktop и использует Windows PowerShell 5.1 вместе со встроенным в DSH Node, чтобы исправить профиль desktop по умолчанию. Она останавливается, если новый бандл отсутствует или всё ещё выбран старый бандл. Она не меняет политику возраста выпуска. Для другого профиля запустите `migrate-profile.ps1 -ProfileDirectory <absolute-directory>` для предварительного просмотра, затем добавьте `-Apply`, когда будете готовы.

В GitHub Release также включён `dsh-computer-use.tgz` для офлайн- или ручной установки; для обновлений через маркетплейс по умолчанию используется установка из реестра.

Для пользователей CLI (профиль web):

```sh
dsh plugin --profile web add dsh-codex-style-computer-use
```

Для диагностики Desktop необходимо использовать **CLI, встроенный в официальное приложение Desktop**:

```powershell
$CuDshInstall = Join-Path $env:LOCALAPPDATA 'Programs\DeepSeek Harness'
& "$CuDshInstall\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop why dsh-codex-style-computer-use
```

При нестандартной установке задайте в `$CuDshInstall` каталог, на который указывает ярлык Desktop. Более старый глобальный `dsh` из npm может отвергнуть профиль desktop. Не добавляйте `resources/runtime/bin` в глобальный PATH и не устанавливайте отдельный pnpm для этой задачи. Для установки по-прежнему предпочтителен интерфейс плагина.

## Встроенный skill

Инструменты управления остаются заблокированными, пока сессия не выдаст фразу-подтверждение, которая есть только в `skills/computer-use/SKILL.md`. Это сделано намеренно — такова самая честная и строгая реализация принципа «сначала прочитайте руководство, потом управляйте», потому что ни один слой инструментов не может увидеть, прочитала ли модель документ.

Плагин регистрирует встроенный skill через `ctx.skills.register()`, когда этот сервис доступен. Если сервиса нет, `computer_use_activate` возвращает то же руководство, абсолютный путь к его исходному файлу и список инструментов в области действия. Требование фразы-подтверждения и все существующие проверки подтверждений и тормоза по-прежнему действуют.

## Совместный ввод в 1.2.0-rc.2

Этот предварительный выпуск вводит немедленный перехват управления человеком, автоматическое ожидание после 2 секунд продолжающегося ввода и возобновление после 3 секунд тишины. Ожидание происходит локально, без опроса модели. Прерванные записи требуют нового чтения фактического результата и никогда не воспроизводятся слепо. Отмена на стороне хоста освобождает принятый автоматизацией ввод, не создавая новой постоянной паузы. Существующая обработка главного окна DSH Pet и восстановления исходного положения поверх остальных окон сохраняется.

Настроенные маршруты GLM 5.3 Max, GLM 5.3 Flash и DeepSeek Flash прошли контролируемый тест протокола продолжения. Нативный ввод и физические горячие клавиши проверялись отдельно; это не общий бенчмарк рабочего стола или компьютерного зрения. Область проверки описана в [проверке выпуска](docs/RELEASE-1.2.0-rc.2.md).

## Управление по требованию в 1.1

- **Инструменты для каждого Агента:** бездействующие Агенты видят `computer_use_activate`, `computer_ctrl` и `computer_ask`. Успешная загрузка skill computer-use, получение фразы-подтверждения или активация открывают этому Агенту 19 инструментов рабочего стола вместе с точкой входа активации. Другие Агенты и дочерние Агенты активируются независимо. Поддерживаются нативные вызовы и Node `run_code`. Активация не запускает управление и не снимает человеческий тормоз.
- **Наблюдаемые цели UIA:** запрос по имени/id в ограниченной области возвращает непрозрачный дескриптор цели. Используйте его для действий по шаблонам; явно включаемый `rebind:true` разрешает восстановление по уникальной идентичности или семантике после замены в том же окне. Изменённый контекст, неоднозначность и неполное сканирование приводят к отказу. Широкие запросы пропускают дескрипторы восстановления, если не указан `targets:true`; создание вспомогательных «свидетелей» для большого списка стоит дополнительной нативной работы.
- **Инкрементальные наблюдения:** передайте идентификатор предыдущего наблюдения как `since` вместе с тем же запросом. Дельты сохраняют добавления, изменения, удаления и порядок. Снимки изолированы по Агентам: не более 64 проиндексированных наблюдений и 4 МиБ сохранённого JSON на хранилище. `snapshot` извлекает сохранённый исторический результат; `offset` и `limit` постранично читают его массивы. Отсутствие базового снимка, изменение области, неполные доказательства или слишком большая дельта приводят к возврату полного вывода.

Пределы кэша и границы восстановления описаны в [подробном протоколе](skills/computer-use/references/progressive-control.md). Снимки UIA сохраняют поля, возвращённые провайдером, в пределах существующих ограничений провайдера; извлечение истории не заменяет свежую проверку результата.

## Инструменты

| Группа | Инструменты |
|---|---|
| Активация | `computer_use_activate` |
| Наблюдение | `computer_state` `computer_shot` `computer_ocr` `computer_marks` `computer_uia` |
| Действие | `computer_click` `computer_move` `computer_drag` `computer_scroll` `computer_select` `computer_key` `computer_type` `computer_uia_act` `computer_window` `computer_clip` |
| Поток | `computer_wait` `computer_batch` |
| Мета | `computer_ask` `computer_ctrl` |

`computer_marks` возвращает нумерованные метки для элементов, найденных на экране; `computer_marks {shot:true}` дополнительно сохраняет аннотированное изображение. `computer_shot` возвращает обычный снимок экрана, а на маршрутах с поддержкой изображений — нативное вложение-изображение. Метка — это идентификатор снимка: он сверяется с идентичностью окна
и выборочно проверенными пикселями до отправки любого ввода, поэтому устаревшая метка отклоняется, а не приводит к клику в неверном месте.

## Режимы подтверждения

Если хост сообщает об автоматическом отказе при отключённых запросах как «пользователь отклонил инструмент», см. [патч атрибуции подтверждений DSH и регрессионный тест](docs/APPROVAL-ATTRIBUTION.md).

`automationMode` задаётся в настройках плагина, значение по умолчанию — `standard`:

| Режим | Наблюдение | Действие |
|---|---|---|
| `read-only` | разрешено | запрещено |
| `standard` | разрешено | каждое действие запрашивается через карточку подтверждения хоста |
| `autonomous` | разрешено | разрешено, высокорисковые операции всё равно требуют подтверждения |
| `unrestricted` | разрешено | разрешено (отказоустойчивость воркера и ограничение частоты по-прежнему действуют) |

Высокорисковые операции (закрытие окна, `alt+f4`, `win+r` и подобные) требуют подтверждения в любом режиме. Поля паролей
определяются через `IsPassword` в UI Automation и по умолчанию отклоняются.

## Модель безопасности

- **Совместный ввод** — обычная активность пользователя разрешена, пока агент думает, наблюдает или готовится. Во время фактического воздействия набор текста, прокрутка и нажатия кнопок немедленно уступают управление; для перемещения указателя допускается смещение до 16 пикселей. Продолжающийся ввод или удержание клавиши/кнопки в течение 2 секунд включает автоматическое ожидание. После отпускания и 3 секунд тишины агент должен проверить текущую цель и продолжить исходную задачу, не воспроизводя слепо частичные записи. Мягкий бледно-жёлтый градиент по краю обозначает, что управление у человека.
- **Ручная пауза** — только физическая комбинация `Ctrl+Esc` включает постоянный тормоз ввода; `Ctrl+Alt+R` возобновляет работу. Обычный Esc, набор текста, прокрутка, расстояние и частота перемещения указателя и угол экрана такую паузу не создают. Явные остановки для вопроса и диагностики остаются отдельными.
- **Выход** — `Ctrl+Alt+Q` завершает сессию: оверлей исчезает, его обработчики снимаются, а дальнейшее
  воздействие отклоняется до тех пор, пока в одном из следующих шагов не будет открыто новое.
- **Тормоз — это факт о машине, а не об одном процессе** — включённое состояние сохраняется,
  и каждый воркер его принимает, включая запущенный позже из оболочки.
- **Аудит** — каждое воздействие добавляется в `$DSH_HOME/data/computer-use/audit.jsonl` с
  очисткой аргументов.
- **Аварийный выключатель самого плагина** — при `DSH_COMPUTER_USE_KILL=1` плагин отказывается запускаться;
  `dryRun: true` только имитирует воздействия и записывает их в журнал.

## Конфигурация

| Ключ | По умолчанию | Значение |
|---|---:|---|
| `automationMode` | `standard` | режим подтверждения (см. выше) |

## MCP-сервер

`mcp/` — MCP-сервер stdio без зависимостей поверх того же ядра, для клиентов, которые говорят на MCP, а не на Cordis:

```sh
node mcp/src/index.js
```

Встроенный сервер сообщает версию этого корневого пакета. Он запускается в режиме только наблюдения.
Запускающий его хост может установить `DSH_CU_ALLOW_INPUT=1`, когда он владеет авторизацией на действия с рабочим столом;
вызовы инструментов MCP не могут включить ввод. Инструмент совместимости `cu_approve` лишь сообщает это правило и
никогда не даёт согласия. Политика `automationMode` в DSH принадлежит адаптеру Cordis и не является
службой подтверждений MCP. `DSH_CU_DRY_RUN=1` имитирует ввод, который хост уже разрешил.

Оба адаптера используют одну и ту же грамматику клавишных команд, правила отказа пакета и продолжения,
а также отображение координат изображения. MCP возвращает структурированные метаданные захвата и одно последнее изображение PNG/JPEG, без
сериализации байтов изображения в текст JSON. `cu_hold` / `cu_free` резервируют или освобождают сцену между
действиями; `cu_release` завершает цикл работы с рабочим столом. `cu_drag` принимает проверки `expectCursor` и `hwnd`.
MCP предоставляет меньший набор инструментов; интеграция человеческих вопросов и жизненного цикла хоста,
специфичная для DSH, обеспечивается адаптером Cordis.

## Разработка

Проверки выпуска публикатора по умолчанию используют официальный реестр npm. Если этот источник недоступен в вашей сети, `CU_REGISTRY` выбирает явное зеркало для команды `check`, работающей только на чтение; результат в JSON содержит `registry` и `authoritative`. Пример в PowerShell (влияет только на текущую оболочку):

```powershell
$env:CU_REGISTRY = 'https://registry.npmmirror.com'
node scripts/release-channel.mjs check 1.2.0
Remove-Item Env:CU_REGISTRY
```

Код выхода `0` означает, что версия прошла 24-часовую проверку публикатора, `2` — что она всё ещё «остывает», а `1` — что проверка не удалась. Сетевая ошибка не доказывает, что пакет не опубликован, а зеркала могут отставать. `promote` всегда перепроверяет и записывает `https://registry.npmjs.org`, игнорируя `CU_REGISTRY`; для этого нужен доступ к этому источнику, при необходимости через прокси-конфигурацию npm. Этот инструмент публикатора не входит в установку для конечных пользователей. См. [процедуру выпуска](docs/RELEASE-1.2.0.md).

Репозиторий поставляет набор защитных проверок, которые охраняют перечисленные инварианты — время жизни цикла,
протокол «вопрос/тормоз», классификацию операций, шлюз skill и подключение встроенного skill:

```sh
pwsh -NoProfile -ExecutionPolicy Bypass -File build/run-guards.ps1   # all guards
node build/verify-tools-schema.mjs                                   # tool-schema load guard
```

Определения инструментов компилируются через настоящий DSL `@deepseek-ai/dsh-tools`, поэтому ошибка в схеме обнаруживается
здесь, а не роняет дерево плагинов хоста при перезапуске. Некоторые проверки компилируют нативный
воркер и работают только в Windows.
