# On-demand tools, observed targets and incremental observations

Read this when interpreting a delta, recovering a replaced UIA control, or diagnosing tool visibility.

## Tool visibility

With progressiveTools enabled, idle Agents see computer_use_activate, computer_ctrl and computer_ask. A successful computer-use skill load, receipt acknowledgement or activation exposes the 19 desktop tools to that Agent; the activation entry remains available too. Other Agents and children activate independently. The operating policy, skill receipt, cycle ownership and human brakes continue to govern execution. Capability activation itself performs no desktop call. A legacy host can set progressiveTools:false to expose the desktop tools globally.

## Native target recovery

1. Query a known window, for example computer_uia {hwnd:321,role:"Button",name:"Save"}.
   Recovery handles are generated by default for scoped name/id queries. Broad inventories skip this extra native work; use targets:true with a concrete hwnd when handles for the whole list are needed, or targets:false to disable them. Ordinary fields and incremental observations remain available either way.
2. Select the intended result using its visible label, context and task. Pass its opaque target to computer_uia_act {target:"<returned handle>",action:"invoke"}.
3. If the native control was replaced while the task/context remains valid, rebind:true allows a new bounded scan. A unique AutomationId must retain the recorded semantics and ancestors. If that identifier disappeared, a unique name/role/class/pattern/ancestor match may be used. A changed meaning, duplicate identity, ambiguous semantics, incomplete scan, changed window title/geometry/process or expired handle refuses before action.

Targets are scoped to this Agent's retained observations and the native worker's cache (512 identities; five minutes from observation). Worker replacement or human takeover invalidates actionable targets; retained historical snapshots can still be read with `targetsValid:false`. No coordinates are guessed during UIA recovery. This feature applies to UIA pattern actions; M-mark clicks remain snapshot/geometry checked and still require refreshing after scrolling/navigation. A recovered control is not proof of the business outcome: inspect readback or query the relevant state.

## Incremental queries and full retrieval

When retention succeeds, the first query returns mode:"full" and observation:"O…". Repeat every original query parameter and add since:"O…" for a fresh comparison. Changes are returned in delta.elements for computer_uia, or delta.windows/delta.uiaFlat for computer_state. Resource pressure can return the current full value without an observation ID; do not invent a retrievable snapshot.

- added and changed contain {key,element}, with the complete current element, not just a changed field.
- removed contains identity keys. Delete those records; replace changed records; insert added records.
- order is supplied whenever array membership/order changed, and lists the resulting key order.
- An element key is its target handle when supplied, otherwise uia:<pid>:<runtimeId>. A window key is window:<pid>:<hwnd>.
- Non-array metadata is always the current metadata. The next observation ID identifies the reconstructed complete state and can be the next since base.

The result contains no hidden duplicate full element array. Retained snapshots preserve all provider-returned fields. `computer_uia {snapshot:"O…"}` or `computer_state {snapshot:"O…"}` retrieves the retained full value without another capture; it returns `snapshotHistorical:true` and the original `capturedAt`. Compact action feedback snapshots use `computer_state`. Explicit `offset` (nonnegative integer) and `limit` (1–80) page the main arrays: elements, uiaFlat, windows and ancestors. `page.fields` reports totals, returned counts and next offsets. A paged response omits the duplicate full `uiaRoot` and reports it in `page.omittedFields`; it does not mutate the cached snapshot. Omit pagination for full retrieval.

Each store indexes at most 64 observations and retains at most 4 MiB of JSON across Agents, with Agent-isolated access. Snapshots expire after 24 hours and may be evicted earlier. Opt-in archived feedback uses the dedicated `observation-cache` directory, limited to 64 managed snapshots and 32 MiB total, also with a 24-hour TTL. Lazy cleanup runs on saves and periodically on reads; it needs no persistent timer and handles old managed files after process restart. It only removes manifest-owned, verified files, never arbitrary files or symlinks. Expired/missing snapshots report unavailable; a missing `since` base instead returns a fresh full result with `resetReason`.

Disk failure returns `archive.status:"memory-only"` when a bounded in-memory snapshot remains available. Disk-full, unavailable storage and capacity failures do not repeat input. If memory is under pressure or the value cannot fit, the current full result is returned without a fake observation ID, with `archive.status:"uncached"`, `reason:"memory-pressure"`, `fallback:"inline"`. Existing disk history can still be explicitly read under pressure. Automatic compact feedback that cannot retain a retrievable snapshot returns its already-read raw evidence as `observation.inlineEvidence` and marks `feedback.detail:"full"`; this fallback is exempt from the normal 6 KiB extra-text budget and performs no extra query.

`computer_ctrl {action:"clear_cache"}` clears this Agent's retained observations and recorded owned cache files without opening a desktop cycle. It reports `cleared`, `filesRemoved`, `bytesFreed` and `retainedOnFailure`; an indeterminate deletion count is reported as unknown rather than success. It does not clear another Agent's cache, screenshots, attachments or user documents. Deletion failures prevent unbounded new disk writes when the quota is full.

Truncated observations, missing/duplicate element identities and scope changes use a full response. The plugin also chooses full when a delta would be larger. This is a bounded observation of what the UIA provider returned; it does not claim that a truncated UIA tree contains every control in the application.
